# LTX-2.5 Studio — runtime dependencies.
#
# Every direct dependency is pinned to ONE exact version: the versions verified
# on real weights on 2026-11-16 (transformers 5.23.0 and the companions uv
# resolves with it for the Space: Linux x86_64, Python 3.12, torch 2.11.0).
# A range is re-resolved on every Space rebuild, so the image would get whatever
# is newest that day instead of what was tested. tests/test_requirements_exact.py
# fails on any range, except on a line marked `# platform-provided` for a package
# the Spaces platform installs itself. Bump a pin only after verifying it.
#
# Fallback if the int8 load misbehaves on the Space: transformers==5.22.2 with
# exactly the same companion pins (uv resolves the identical set for it).
#
# Dev/test tooling (pytest, ruff) is NOT here — it lives in pyproject.toml's
# [project.optional-dependencies] dev extra, so the Space image stays lean.

# --- NOT PINNED, DELIBERATELY -------------------------------------------------
# `spaces` is intentionally absent. The Spaces platform pins its own version
# (live Spaces reported 0.49.3 / 0.50.0 / 0.50.4 while PyPI had 0.51.1; PyPI
# has had 0.52.0 since 2026-11-13), and a conflicting pin here breaks pip
# resolution at build time. See docs/PLAN.md §5.1. The 2.3 repo's own
# AGENTS.md:19 states this rule and its requirements.txt:2 then violated it.
# The import is guarded in ltx25_studio/zerogpu.py so local dev works without it.
# ------------------------------------------------------------------------------

# --- torch trio: pinned exactly, and pinned TOGETHER --------------------------
# ZeroGPU supports exactly torch 2.8.0 / 2.9.1 / 2.10.0 / 2.11.0 (CUDA 12.8;
# sm_120 Blackwell needs cu128+). 2.11.0 is the ceiling.
# Trap: torchvision 0.28.0 hard-declares torch==2.13.0, so letting torchvision
# float silently drags torch past the ceiling. torchaudio must match torch
# exactly or the C++ ABI mismatch crashes the whole audio path on import.
#
# NOTE for whoever bumps these: tests/test_torch_trio_drift.py guards all three
# together — torch, torchaudio AND torchvision — so a mismatched bump fails the
# gate rather than the Space. Bump them as a set and let the test confirm it.
torch==2.11.0
torchvision==0.26.0
torchaudio==2.11.0

diffusers @ git+https://github.com/huggingface/diffusers@ac56fa2f25c1c15b4cbaa1e0b3255e9bc38c06dc

# --- model stack --------------------------------------------------------------
# transformers 5.23.0 is the version the 12B text encoder and the pipelines were
# verified with on real weights. `ltx25_studio/enhance.py` loads the prompt
# enhancer as a plain `Gemma4ForConditionalGeneration` from a pre-quantised
# checkpoint (`google/gemma-4-E2B-it-qat-mobile-transformers`, quant_method
# "gemma"). That quantizer is registered from transformers 5.15.1 and is pure
# torch, so the enhancer needs 5.15.1 or newer and runs on CUDA, MPS or CPU.
#
# tokenizers is pinned beside transformers because it decides whether
# transformers imports at all: transformers 5.15.1 raises ImportError with
# tokenizers 0.23.3.
transformers==5.23.0
tokenizers==0.23.3
accelerate==1.15.0
peft==0.20.0                # LoRA backend; USE_PEFT_BACKEND gates load_lora_weights
safetensors==0.8.0
huggingface_hub==1.33.0
hf_xet==1.8.0

# `kernels` is required by the DIFFUSION DECODER, i.e. by stage 2 -- not by the
# single-stage path, which is why nothing missed it until stage 2 was wired.
# It fetches the NATTEN kernel from the Hub at runtime; upstream is explicit that
# a local `natten` install is NOT used, so installing natten instead does nothing.
#
# Without it the decoder falls back to an uncompiled FlexAttention processor that
# materialises the full score matrix and needs TENS OF GB at video resolutions.
# `set_attention_backend` is not an escape: no backend other than `flex` accepts
# the BlockMask. See ltx25_studio/pipelines.py::_stage_2_parts.
kernels==0.16.2

# `bitsandbytes` is the int8 path for ZeroGPU, where bf16 does not fit: the
# packing peak is snapshot + packed + image, and bf16 gives 152.4-156.4 GB
# against a 150 GB cap. See docs/ZEROGPU_DISK.md 4.2 for the derivation.
#
# ANY PIN HERE MUST STAY ABOVE THE FLOOR OF 0.46.0, AND THAT IS NOT DIFFUSERS'
# FLOOR. diffusers mandates 0.43.3 (bnb_quantizer.py:70). The binding constraint
# is ZeroGPU: spaces/zero/torch/bitsandbytes.py no-ops _patch/_unpatch/_move
# only ABOVE 0.46.0, wired at patching.py:328/355/445. Below that the packer
# would try to move quantised tensor subclasses itself. There is no equivalent
# module for torchao at any version, which is what makes bnb the supported path
# rather than a preference.
bitsandbytes==0.50.2

# --- UI -----------------------------------------------------------------------
# gradio 5.x is END OF LIFE (last stable 5.50.0, 2025-11-21).
#
# PINNED EXACTLY, and it MUST EQUAL `sdk_version` in the Space README frontmatter.
# A range brackets 6.24.0 today and resolves to 6.30 tomorrow while sdk_version
# still says 6.24.0 — the Space would then serve one gradio and the environment
# would allow another. A drift test asserts the two agree. Upgrading is
# deliberately two edits: this line and sdk_version.

# event-listener validators.
gradio==6.24.0
